### 2.3 — Is the `methodology_variant` discriminator design spatially/methodologically sound? YES.

I verified the `weight_variant` pattern the ADR mirrors is real and behaves as D4 claims:
`transform/models/intermediate/schema.yml` (`int_osm_poi_plr_weighted`) carries `weight_variant` as an
enumerated column that is part of the `unique_combination_of_columns` grain test. D4's design is sound:

- **Orthogonality is correct.** `weight_variant` (kernel/bandwidth — a *spatial-smoothing* axis) and
  `methodology_variant` (faithful/improved — a *type-selection/curation* axis) vary independently; a
  fully-qualified OA row is keyed on both plus the taxonomy/space/time grain. Collapsing either into
  the other would confound "wider catchment" or "smoothed" with "we changed which types count" — the
  exact confound the separation exists to prevent. Keeping them as two columns is the right encoding.
- **No blend value is the right enforcement.** Making Run 3 (comparison) a *derived* contrast of the
  `faithful` and `improved` rows — rather than a third `combined`/`blended` enumerated value — turns
  D3's "never blend" rule into a schema-level structural invariant (accepted_values + grain), not a
  convention a downstream author can forget. From a methodology-integrity standpoint this is stronger
  than the spike could offer and I endorse it.
- **Consistency with the causal-tier deferral.** D3/D4 correctly keep type dropping/weighting the
  *sole* province of the Workstream-2 causality-first curation (OA-B.4 #173), so `improved` rows can't
  be silently manufactured inside Run 1. Methodologically clean.

### 2.4 — Any new spatial-methodology concern introduced by ADR formalization? NONE blocking.

Formalizing the spike as an ADR surfaced nothing that wasn't visible at spike stage. Two minor
observations, both already handled, neither a condition:

1. The invariance `Σ_a weighted_count_level = hard city total_level` holds **only after** the C-1
   leakage guard restores dropped mass; without the guard the equality fails in large low-density PLRs.
   The ADR states this dependency correctly (C-1 ships the guard *and* the invariance test as its
   proof), so the two are bound in the right order. No drift — just re-confirming the sequencing.
2. D4's grain key lists `poi_domain_h, poi_category_h, poi_type_h` together; the three LQ levels are
   nested, so the physical mart(s) must either be long-format-per-level or carry NULL parent-key
   conventions per level. This is an OA-A.2 implementation detail, not an ADR-level decision, and the
   ADR correctly leaves it to the build ticket. I flag it only so OA-A.2's reviewer confirms the
   grain/uniqueness test is well-defined across the three nesting levels (a level discriminator or
   per-level models), which is where the R-C1 gate re-binds anyway.

## 3. Risks

1. OA-A.2 could implement the D4 grain ambiguously across the three nesting levels (level discriminator
   vs NULL-parent convention); the uniqueness test must be unambiguous. Mitigated: re-checked at
   OA-A.2's own R-C1 gate.
2. C-1's invariance test is only meaningful *with* the leakage guard applied; shipping the test without
   the guard would pass vacuously on small PLRs and hide the large-PLR bias. Mitigated: ADR binds guard
   + test together on #166 (blocking).
3. Residual (unchanged from P0.1): faithful Run 1 OA will diverge from the 2018 golden partly because
   the thesis used an effectively unbounded distance spread vs the finite truncated bandwidth — a
   documented *methodological* divergence under Epic B directional framing, not a data error.
