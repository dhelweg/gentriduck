## 2. Is the faithful-vs-improved, never-blended two-workstream design (D3) theoretically sound?

Yes, and it is the design decision I most want to see locked. Two questions were posed; both resolve in
favor.

### 2.1 Does the separation correctly isolate the two distinct scientific questions?
The design maps cleanly onto the only two questions the OA revival can legitimately ask, and keeps them
non-confoundable:

- **Faithful (Run 1, Epic B) = "does the 2018 thesis's OA construct still hold?"** All types, no
  curation, thesis semantics, anchored to the 2018 golden (`oa_*`/`prev_oa_*`, H1–H3c). This is a
  *reproduction/reproducibility* question. It must include the thesis's non-causal and sign-ambiguous
  types precisely because removing them would no longer be a faithful test of the thesis's own claim.
- **Improved (Run 2, Epic C) = "can we build a better-grounded offering-advantage signal?"** Causality-
  first tiered curation with data-driven confirmation, anchored to the outcome/MSS. This is a
  *construct-improvement* question.

D3's firm rule correctly identifies the confound that blending would create: a single merged score would
conflate *"the world changed / OSM differs"* (Run 1's question) with *"we changed the metric"* (Run 2's
question). These are orthogonal sources of variation, and averaging them produces a number that answers
neither question — the classic reproduction-vs-refinement confound. Keeping them un-blendable is the
methodologically correct way to preserve the interpretability of *each* result. This is faithful to the
invasion-succession / lead-lag logic: Run 1 tests whether the historical succession signal replicates;
Run 2 tests whether a theory-refined succession signal predicts better. Blending would destroy the
directional-revival framing of Epic B (CLAUDE.md §Epic B) by contaminating the "does it still hold"
verdict with metric changes.

I also endorse D3's explicit disambiguation that "causal" in the Workstream-2 tier rule means
*theoretical causal-plausibility as a selection filter*, **not** causal inference (DiD/event-study,
#80). This is exactly the distinction my gate exists to protect: the tier rule is a theory-driven
*variable-selection* device, and conflating it with causal-effect estimation would be a category error
that over-claims what OA can establish. The ADR names and forecloses that conflation. Good.

### 2.2 Does structural un-blendability serve public-facing scientific honesty/reproducibility?
Yes, materially. D4 makes "never blend" a **structural invariant** rather than a convention: because
`methodology_variant ∈ {faithful, improved}` is enumerated, tested (`accepted_values`), and part of the
grain, and because Run 3 (comparison) is a *derived* contrast rather than a third enumerated value,
**there is no schema slot for a `blended`/`combined` score to exist in.** A downstream author cannot
accidentally (or expediently) produce one; the pipeline would fail its accepted-values/grain test. For a
public-facing statistics site whose credibility rests on not silently conflating "the neighborhood
changed" with "we changed our ruler," this matters. It means the site's honesty about *which* question
a number answers is enforced by the data model, not by reviewer vigilance — which is exactly the kind of
guarantee that survives staff turnover, time pressure, and the temptation to show one tidy "gentrification
score." The site shows the **comparison** (Run 3), never a blend. This is the strongest possible
operationalization of the scientific-honesty commitment and I fully endorse it.

**Verdict on Point 2: the faithful/improved never-blended split is theoretically sound; it isolates the
reproduction question from the refinement question without confound, and the `methodology_variant`
discriminator turns scientific honesty into a structural invariant that materially protects public
credibility.**

## 3. Does ADR-level locking foreclose any domain-theory revision path?

No. This was my sharpest test of the "ADR vs provisional spike" upgrade, and the design passes because
of *where* it draws the locked/open boundary.

- **What is locked (faithful side) is definitionally fixed anyway.** The 3-level nested parent-relative
  LQ (D1) is the *faithful* construct: its entire purpose is to reproduce the 2018 thesis's own OA
  (`71_oa.sql`). One cannot "revise" the faithful construct on domain-theory grounds without it ceasing
  to be faithful — reproduction fidelity is precisely a commitment that *should* be locked. Locking it as
  an ADR forecloses nothing legitimate; it is the correct target for an ADR-level commitment.
- **The revision path domain theory actually needs is deliberately kept open — and routed to a future
  ADR.** Every place where evolving gentrification theory would want to intervene — *which* POI types
  count, how they are weighted, how sign heterogeneity is handled — is channeled into **Workstream 2**
  (improved), whose tier rule is explicitly deferred to a *future* ADR (OA-B.4, #173). The type-curation
  ADR does not yet exist and is named as forthcoming. So the ADR-0017 commitment does not lock the
  substantive theory choices; it locks only the faithful reproduction and the experimental-design
  scaffolding, and it *creates* the open slot (Workstream 2 + its own R-C1 gate) for theory-driven
  revision. This is the opposite of foreclosure — it is a structured, auditable revision channel.
- **The parameters that could plausibly need revision remain amendable via normal ADR process and are
  already hedged.** The bandwidth headline (1000 m) and sweep ({500,1000,1500} m) are fixed, but C-4
  makes bandwidth-fragility a *reportable substantive finding*, so if the succession signal turns out to
  live at a different spatial grain, that surfaces as evidence rather than being buried — and a scale
  change would be a routine ADR amendment, not a structural break.
- **General ADR-hygiene point.** An ADR is a *decision record*, not an immutable law; the repo's own
  convention allows supersede/amend. ADR-0017 explicitly "does not change any accepted ADR" and extends
  ADR-0008/0010/0005. Formalizing the P0.1 spike decisions as an ADR is the *correct* maturation step:
  the spike settled the method, and a construct this load-bearing (it underpins all of H1–H3c and the
  whole Run 1/2/3 spine) should be pinned so downstream tickets and the PM's pre-integration check have
  a single authoritative reference, rather than tracing a provisional spike doc.

**Verdict on Point 3: no foreclosure. ADR-0017 locks only the reproduction-fidelity construct and the
experimental-design scaffold — both correct targets for a firm commitment — while deliberately keeping
the substantive domain-theory revision path open and routed to a dedicated future ADR (OA-B.4 #173) with
its own R-C1 gate. Formalization is the right maturation of the spike, not a premature lock-in.**
